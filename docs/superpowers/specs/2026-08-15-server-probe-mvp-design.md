# 服务器探针 MVP 约束文档

**状态：待用户审阅**

## 1. 目标

构建一个自托管的服务器状态探针，供单一管理员查看多台 Linux 服务器的健康状态。它应保持低资源占用，并将可被网络访问的功能严格限制为指标上报和管理员查看。

本项目以 `hochenggang/kunlun-server-python` 的中心端加客户端思路为参考，但不复用其 Python 单文件服务端或 C 客户端实现。

## 2. MVP 边界

### 包含

- 最多管理 50 台 Linux `amd64` 或 `arm64` 服务器。
- 每台服务器运行一个主动上报的 Agent，默认采样间隔为 30 秒。
- 显示在线、延迟、离线和未完成注册四种状态。
- 采集 CPU 使用率、内存使用量、根分区磁盘使用量、`load1`、入站与出站网络速率。
- 提供服务器总览、单服务器详情和最近 24 小时趋势图。
- 提供注册、停用、移除 Agent 的管理员流程。
- 使用 Docker Compose 部署中心端，并为 Linux Agent 提供 systemd 服务文件。

### 不包含

- 远程 Shell、命令执行、重启、文件传输或任何 Agent 控制通道。
- 多用户、角色、组织或公开状态页。
- Windows、macOS、容器内 Agent。
- 进程列表、日志收集、端口扫描、自动发现、插件系统。
- Prometheus、Grafana、外部告警渠道和移动端应用。
- 数据库高可用、跨区域复制或云托管服务。

## 3. 系统架构

```text
Linux Agent -- mTLS HTTPS --> ingest.<domain> -- Caddy --> Probe Server -- SQLite
                                                           |
Browser -- HTTPS + TOTP --> monitor.<domain> -- Caddy ----+
```

- Agent 仅向 `ingest.<domain>` 发起出站连接，绝不监听网络端口。
- 浏览器仅访问 `monitor.<domain>`。此站点只用于管理员登录和查看数据。
- Caddy 是唯一绑定主机公网端口的容器。防火墙只允许 TCP `443`；数据库和 Probe Server 不暴露端口。
- Probe Server 在受限容器内运行，处理认证、状态推导、持久化和服务端渲染页面。
- SQLite 数据仅通过本机挂载卷提供给 Probe Server。

## 4. 技术栈

| 范围 | 选择 | 约束与理由 |
| --- | --- | --- |
| Agent | Go，直接解析 Linux `/proc` 并调用 `statfs` | 单二进制、无运行时、低内存，避免为单一监控用途引入大型采集框架。 |
| 中心端 | Go 标准库 `net/http`、`html/template` | 控制依赖数量，将 API、状态规则和管理页面置于同一小型进程中。 |
| 数据库 | SQLite 3，WAL 模式 | 适合 50 台主机的 MVP，备份简单，没有额外常驻数据库进程。 |
| 图表 | 固定版本、本地托管的轻量图表脚本 | 不从 CDN 加载资源，不引入 Node、Vue 或前端构建运行时。 |
| HTTPS | Caddy | 自动管理公网 TLS 证书，并将公网入口集中到一个容器。 |
| 部署 | Docker Compose + 非 root 镜像 | 中心端运行时只有 `caddy` 和 `probe-server` 两个容器。 |
| Agent 守护 | systemd | 使用受限系统用户和系统级沙箱选项。 |

构建期可以使用 Go 工具链和静态资源构建脚本；生产运行时不依赖它们。

## 5. 资源与容量约束

- Agent 的长期 RSS 目标不高于 20 MiB，5 分钟平均 CPU 使用率不高于 0.5%。
- Agent 单次上报的请求体不得超过 8 KiB；失败时内存中只保留最新一份样本。
- 中心端以 50 台活跃 Agent、每 30 秒一份样本作为设计上限。
- 原始样本保留 30 天。每天执行一次清理作业；数据库超过 2 GiB 时先删除最旧的原始样本，保证最新状态持续可写入。
- MVP 不保存 Agent 本地离线队列、不进行历史数据聚合，也不保存超过 30 天的样本。

## 6. 指标、状态与数据模型

### 采集规则

- CPU 使用率由相邻两次 `/proc/stat` 采样计算。
- 内存使用量来自 `/proc/meminfo`，可用内存按 Linux `MemAvailable` 计算。
- 磁盘只采集根分区 `/`，不采集独立挂载点或路径列表。
- 网络速率由相邻两次 `/proc/net/dev` 的字节计数差值计算。计数器回绕或重置时，该周期速率归零。
- `load1` 来自 `/proc/loadavg`。
- 服务端接收时间是所有状态和图表的标准时间，客户端时钟只用于诊断日志。

### 状态规则

| 状态 | 规则 |
| --- | --- |
| 未完成注册 | 管理员已创建节点，但尚未收到第一份有效上报。 |
| 在线 | 最近有效上报不超过 90 秒。 |
| 延迟 | 最近有效上报超过 90 秒且不超过 180 秒。 |
| 离线 | 最近有效上报超过 180 秒，或证书被吊销。 |

### 逻辑数据表

- `admins`：唯一管理员的密码哈希、TOTP 密钥和恢复码哈希。
- `sessions`：带过期时间的服务器端会话。
- `nodes`：管理员指定的显示名称、节点状态、创建时间、最后上报时间和停用标记。
- `agent_certificates`：节点 ID、证书序列号、签发和失效时间、吊销状态。
- `samples`：节点 ID、服务端时间、CPU、内存、根磁盘、`load1`、入站和出站速率。

所有查询以节点 ID 和服务端时间为索引。系统不自动采集或展示公网 IP、完整主机名、用户数据、命令行、磁盘路径或进程信息。

## 7. 认证与安全约束

### 管理员访问

- `monitor.<domain>` 只允许一个管理员账户。
- 密码使用 Argon2id 哈希，参数为 64 MiB 内存、3 次迭代、并行度 1，且使用随机盐。
- 管理员登录必须通过 TOTP 二次验证。首次初始化生成 10 个一次性恢复码，只存储其哈希。
- 会话 Cookie 必须为 `Secure`、`HttpOnly`、`SameSite=Strict`，使用服务端会话并在 12 小时后失效。
- 所有改写操作均校验 CSRF 令牌和同源请求头。管理界面不提供跨域 API，CORS 默认关闭。
- 登录接口按 IP 和账户名限速为每 15 分钟最多 5 次失败尝试。

### Agent 身份

1. 管理员创建节点，系统生成只显示一次的注册码。注册码有效期 10 分钟，成功或过期后立即失效。
2. Agent 在本机生成私钥和证书请求，通过 `enroll.<domain>` 提交注册码和公钥。
3. 中心端签发节点专属 mTLS 证书。后续上报只接受 `ingest.<domain>` 上持有有效客户端证书的请求。
4. 证书有效期为 30 天。Agent 用仍有效的客户端证书发起续期；停用或吊销节点后，中心端立即拒绝该证书序列号。

Agent 私钥、证书和配置保存在仅 Agent 系统用户可读的目录中，目录权限为 `0700`。日志不得记录注册码、私钥、会话 Cookie、TOTP 密钥或完整认证头。

### 网络与运行时

- `ingest.<domain>` 仅接受 `POST /v1/reports` 和证书续期接口；请求体限制为 8 KiB，节点上报速率限制为每分钟 4 次。
- `enroll.<domain>` 仅接受注册接口，并按源 IP 严格限速。它不返回节点数据或管理信息。
- Caddy 仅将允许的主机名和路径转发给应用；未知主机名、方法和路径返回通用错误。
- Probe Server 以非 root 用户运行，根文件系统只读；只有数据库、证书和临时目录可写。
- systemd Agent 启用 `NoNewPrivileges=true`、`PrivateTmp=true`、`ProtectSystem=strict`、空的 Linux capabilities，并使用专用的非登录系统用户。
- 每次发布锁定 Go 模块和容器镜像版本，并运行 `govulncheck`、`gosec` 和依赖更新审查。

此模型降低攻击面，但不承诺绝对安全。公网 `443` 仍应及时更新系统、Caddy 和应用依赖，并由防火墙和可靠密码保护。

## 8. Agent 上报与故障行为

- Agent 启动时立即采样一次，随后每 30 秒上报。
- 上报失败时按 1、2、4、8、16、30 秒退避；下一轮只发送最新样本，不积累磁盘队列。
- 收到 `401`、吊销响应或证书失效时，Agent 停止正常上报并写入本地错误日志，等待管理员重新注册。
- 收到 `429` 时，Agent 遵守服务端给出的重试时间。
- 中心端使用数据库事务写入样本并更新节点最后上报时间。重复或过期时间窗口外的报告不改变状态。
- 数据库不可写时，中心端返回 `503`；Agent 不会无限重试同一历史样本。
- 服务端重启后根据持久化的最后上报时间重新推导状态，无需后台补偿任务。

## 9. Web 功能与使用流程

### 初始化

首次启动时，中心端只在本机控制台输出一次性初始化链接。管理员设置密码、绑定 TOTP 并保存恢复码后，该链接立即失效。

### 管理流程

1. 管理员登录总览页。
2. 管理员创建节点并填写显示名称，复制一次性注册命令到目标服务器。
3. Agent 完成证书注册并开始上报。
4. 总览页按状态显示服务器，支持按名称和状态筛选。
5. 详情页显示最新指标与最近 24 小时趋势，可停用或移除节点。

页面不会显示注册代码、证书、密码、TOTP 密钥或恢复码。移除节点会立即吊销其证书，并删除该节点的原始样本。

## 10. 部署与备份

- Docker Compose 只发布 Caddy 的 `443` 端口。所有其他容器端口仅在 Compose 网络内可见。
- 域名的 DNS 记录直接指向中心端主机，Caddy 使用该域名获取并续期 TLS 证书。
- SQLite 数据库、Caddy 证书数据和应用密钥使用独立持久卷，权限仅授予相应容器用户。
- 每天创建一次 SQLite 在线备份，保存在主机上由管理员指定的私有备份目录，保留最近 7 份。
- 恢复流程是停止 Probe Server、还原一份完整备份、启动服务并检查最后上报时间。Caddy 无需停止。

## 11. 测试与验收标准

- Go 单元测试覆盖 `/proc` 解析、速率计算、状态阈值、保留策略和认证状态机。
- 集成测试覆盖 SQLite 迁移、一次性注册、无证书拒绝、mTLS 成功上报、吊销后拒绝、请求限流和 30 天清理。
- Web 端到端测试覆盖首次初始化、密码加 TOTP 登录、创建节点、状态筛选和详情趋势图。
- 安全检查要求通过 `go vet`、`staticcheck`、`gosec` 和 `govulncheck`，并验证容器以非 root 用户运行。
- 在 50 个模拟 Agent、30 秒上报间隔下连续运行 24 小时，中心端不得丢失已确认的样本，Agent 不得超过资源预算。
- 对外端口扫描只允许 `443`；Agent 主机不应因本项目新增任何入站监听端口。

## 12. 后续版本候选项

后续优先级由真实使用数据决定：标签和分组、磁盘多挂载点、通知、历史汇总、只读分享页、PostgreSQL 迁移，以及多管理员支持。它们均不属于本 MVP 的交付承诺。
